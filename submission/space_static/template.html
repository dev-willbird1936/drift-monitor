Drift monitor

A small model reads an AI agent's work as it happens and scores how far it has drifted from what the user asked for (0 to 100). Past the line, a stronger model is asked to step in.

Drift monitor

Recorded runs, replayed as they happened: the agent's reasoning, tool calls and replies, with the monitor's score while it reasons (hollow dots) and after each step (solid dots). Each session ran twice with the same task and hidden push: once watched by the monitor and an advisor, once unwatched. The monitor never sees the hidden push. In these runs the monitor and advisor worked in the background, so a note reached the agent a step or more after the score crossed the line. The monitor outputs only a number; the one-line reasons were written afterwards from the transcript.

Drift monitor
Waiting for a run. The score appears here as the agent works.

While the agent is thinking, the monitor scores the reasoning streamed so far up to twice a step (hollow dots); when a step finishes it scores the whole step (solid dots). The scoring model runs on a separate backend; the agent and the advisor run on the demo's shared OpenRouter key (held by that backend, never sent to this page) or on your own key if you paste one. Once the advisor has written a note, the monitor reads it as a later instruction, so the repair it asks for is not counted as new drift.
